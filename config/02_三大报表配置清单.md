# 02 中国三大报表配置清单（资产负债表 / 利润表 / 现金流量表）

> 适用：ERPNext v15（Podman 自建部署）
> 目标：让三大报表符合《企业会计准则》的格式与口径

---

## 一、先懂取数原理，否则报表一定是 0 或不平

### 1.1 三层类型，各管什么

ERPNext 的科目上有三个关键字段，作用完全不同：

| 字段 | 取值 | 作用 |
|---|---|---|
| **Root Type**（根类型） | Asset / Liability / Equity / Income / Expense | 决定科目属于五大类中的哪一类，是科目的"大归口" |
| **Account Type**（科目类型） | Cash / Bank / Receivable / Payable / Fixed Asset / Stock / Cost of Goods Sold / Tax / … | **决定系统的事务行为**（能不能记账、能不能开发票），不决定报表行项 |
| **Account Category**（账户类别） | 如 Cash and Cash Equivalents、Trade Receivables … | ⭐ **决定自定义报表模板取数** —— 这是关键 |

### 1.2 ⭐ 最容易踩的坑：自定义报表全 0

**结论先说**：

> **标准报表**（内置的 Balance Sheet / P&L）多数情况下可以直接靠 `root_type` + `account_type` 自动取数，**即使没设 Account Category 也能出数**。
>
> **自定义报表模板（Financial Report Template）则强依赖 Account Category**。如果你的模板里某一行写的是 `Trade Receivables`，而科目上的 Account Category 写的是别的、或者根本没写，**这一行一定是 0**。

### 1.3 设置 Account Category 的三条铁律

| # | 铁律 | 说明 |
|---|---|---|
| 1 | ⭐ **只有末级科目才设** | 必须 `Is Group = 0`。报表引擎只汇总实际发生业务的**末级科目**。父级科目（如"应付账款"这个组）**不用设** |
| 2 | ⭐ **名称必须与模板一字不差** | 模板写 `Trade Payables`，科目就必须是 `Trade Payables`。差一个字母、大小写不对、多一个空格 → 该行为 0 |
| 3 | ⚠️ **"本年利润"科目绝对不要设 Account Category** | 见下条说明 |

### 1.4 ⚠️ 为什么"本年利润"不能设账户类别（否则资产负债表不平）

自定义资产负债表中通常有一行 `Current Profit / Loss`（本年利润），它**直接按 `root_type in ["Income", "Expense"]` 自动汇总所有收入和费用类末级科目的本期净额**。

也就是说：**ERPNext 已经自动算了一遍当期利润**。

如果你再给"本年利润"科目（4103）设置权益类账户类别，就会出现：

```
收入费用自动算一次  +  权益类科目再算一次  =  利润被重复计算  →  资产负债表两边不平
```

**正确做法：科目 4103 本年利润 → Root Type = Equity，Account Category 留空。**

## 二、配置前的准备：确认你系统里实际可用的 Account Category

**不要照抄网上的名称。** 不同版本、不同本地化包下，Account Category 列表可能不同。

**查看路径**：`Accounting → Accounting Masters → Account Category`

> 也可以用搜索栏直接搜 "Account Category" → 打开列表 → 看**实际的完整名称拼写**。
>
> ⭐ 记下这些名称，配置报表模板时**从下拉框里选**，不要手打。

如果需要更贴合中国准则的分类，也可以**自己新建 Account Category**（如 `流动资产`、`非流动资产`、`流动负债`），然后在科目上引用 —— 两条路都行，关键是**模板与科目两边名称一致**。

## 三、资产负债表

### 3.1 中国准则格式（行项结构）

```
资产
  流动资产
    货币资金
    交易性金融资产
    应收票据
    应收账款
    预付账款
    其他应收款
    存货
    流动资产合计
  非流动资产
    固定资产              ← 按原值减累计折旧后的净额列示
    在建工程
    无形资产
    长期待摊费用
    递延所得税资产
    非流动资产合计
  资产总计
负债和所有者权益
  流动负债
    短期借款
    应付票据
    应付账款
    预收账款
    应付职工薪酬
    应交税费
    其他应付款
    流动负债合计
  非流动负债
    长期借款
    预计负债
    递延所得税负债
    非流动负债合计
  所有者权益
    实收资本
    资本公积
    盈余公积
    未分配利润              ← 含本年利润（不要单独再设类别）
    所有者权益合计
  负债和所有者权益总计
```

### 3.2 行项与取数方式对照

| 报表行 | 取数方式 | 对应的中国科目 |
|---|---|---|
| 货币资金 | Account Category = `Cash and Cash Equivalents` | 1001 库存现金 + 1002 银行存款 + 1012 |
| 应收票据 | Account Category = `Other Receivables`（或自建"应收票据"类别） | 1121 |
| 应收账款 | Account Category = `Trade Receivables` | 1122 |
| 预付账款 | Account Category = `Other Current Assets` | 1123 |
| 其他应收款 | Account Category = `Other Receivables` | 1221 |
| 存货 | Account Category = `Stock Assets` | 1403 / 1405 / 1408 |
| **固定资产** | 公式：`Fixed Assets 科目余额 − Accumulated Depreciation 科目余额` | 1601 − 1602 |
| 应付账款 | Account Category = `Trade Payables` | 2202 |
| 应交税费 | Account Category = `Tax`（若你的系统有该类别） | 2221 及其明细 |
| 未分配利润 | 公式：`Equity 类中利润分配科目 + 本年利润`，或用 `Current Profit / Loss` 行 | 4103 + 4104 |
| **资产总计 / 负债和所有者权益总计** | 公式：= 上方各合计行相加 | — |

> ⚠️ **固定资产要按净额列示**：中国资产负债表列的是"固定资产"净额（原值 − 累计折旧 − 减值准备）。所以这一行**不能只选一个 Account Category**，要用公式把 `Fixed Assets` 减去 `Accumulated Depreciation`。这是很多中国化报表最常见的错误点。

### 3.3 操作步骤

1. 进入 `Accounting → Reports → Balance Sheet`（或搜索 "Financial Report Template"）
2. 若用**自定义模板**：新建 Financial Report Template → Report Type 选 **Balance Sheet** → 按 3.1 的结构逐行添加（Row Type 选 Account Category / Account / Formula）
3. 若只是**调整内置报表**：Balance Sheet → Customize → 修改行项分组
4. 保存 → 设为默认（或另存为"中国资产负债表"）

### 3.4 验证（必做）

> **资产总计 = 负债和所有者权益总计**
>
> 如果不等，按顺序排查：
> 1. 是否给"本年利润"设了 Account Category（最常见）
> 2. 固定资产是否没抵减累计折旧
> 3. 是否有科目漏归入任何一行

## 四、利润表

### 4.1 中国准则格式

```
一、营业收入
  减：营业成本
      税金及附加
      销售费用
      管理费用
      研发费用
      财务费用
二、营业利润
  加：营业外收入
  减：营业外支出
三、利润总额
  减：所得税费用
四、净利润
```

### 4.2 行项与取数方式对照

| 报表行 | 取数方式 | 对应中国科目 |
|---|---|---|
| 营业收入 | Account Category（收入类）或 Root Type = Income 汇总 | 6001 主营业务收入 + 6051 其他业务收入 |
| 营业成本 | Account Category = `Cost of Goods Sold` | 6401 + 6402 |
| 税金及附加 | Root Type = Expense 下对应科目 | 6403 |
| 销售费用 | Root Type = Expense 下对应科目 | 6601 |
| 管理费用 | Root Type = Expense 下对应科目 | 6602 |
| 研发费用 | Root Type = Expense 下对应科目 | 6604（或 5301 结转） |
| 财务费用 | Root Type = Expense 下对应科目 | 6603 |
| 营业外收入 | Account Category（营业外收入类） | 6301 |
| 营业外支出 | Account Category（营业外支出类） | 6711 |
| 所得税费用 | Account Category（所得税类） | 6801 |
| **净利润** | 公式：利润总额 − 所得税费用 | — |

> ⚠️ **主营/其他业务要分清**：ERPNext 的收入和费用科目如果混在一起，营业利润会算错。建议用 **Account Category 区分主营业务与其他业务**，或者用**成本中心/会计维度**辅助。

### 4.3 验证

> **净利润 = 科目 4103「本年利润」的本期发生额（贷方−借方）**
>
> 两者对不上 → 检查是否有损益类科目漏归入报表行。

## 五、现金流量表

### 5.1 ⚠️ 前置动作（不做这步，报表全空）

现金流量表**不能靠 Root Type 自动出数**，必须**先在科目上标记现金流量类型**。

**操作**：打开货币资金及相关的资产/负债科目（1001、1002 等）→ 找到 **Cash Flow Type** 字段 → 设置取值：

| Cash Flow Type 取值 | 含义 |
|---|---|
| Cash | 现金及现金等价物 |
| Cash Equivalent | 现金等价物 |
| Investing | 投资活动 |
| Financing | 筹资活动 |

> 💡 也可以设置 **Cash Flow Mapper**（现金流量映射器）来批量指定哪类科目归入经营/投资/筹资活动。

### 5.2 中国准则格式

```
一、经营活动产生的现金流量
    销售商品、提供劳务收到的现金
    收到的税费返还
    收到其他与经营活动有关的现金
    购买商品、接受劳务支付的现金
    支付给职工以及为职工支付的现金
    支付的各项税费
    支付其他与经营活动有关的现金
    经营活动产生的现金流量净额
二、投资活动产生的现金流量
    收回投资收到的现金
    取得投资收益收到的现金
    购建固定资产、无形资产和其他长期资产支付的现金
    投资活动产生的现金流量净额
三、筹资活动产生的现金流量
    吸收投资收到的现金
    取得借款收到的现金
    偿还债务支付的现金
    分配股利、利润或偿付利息支付的现金
    筹资活动产生的现金流量净额
四、汇率变动对现金的影响
五、现金及现金等价物净增加额
    加：期初现金及现金等价物余额
六、期末现金及现金等价物余额
```

### 5.3 验证

> **现金及现金等价物净增加额 = 货币资金期末余额 − 期初余额**

## 六、配置顺序建议（照这个顺序做，最省事）

| 顺序 | 动作 | 为什么 |
|---|---|---|
| 1 | ⭐ 先查 `Accounting → Account Category`，记下实际名称 | 后面所有配置都依赖它 |
| 2 | 建好会计科目表（见 01 号 CSV），并把 Account Type 设对 | 应收/应付/COGS/固定资产/累计折旧 这五个是硬要求 |
| 3 | 给末级科目补 Account Category（**父级和"本年利润"不设**） | 报表取数靠它 |
| 4 | 给货币资金类科目设 Cash Flow Type | 现金流量表的前置 |
| 5 | 配资产负债表 → 验证平衡 | 先配最基础的 |
| 6 | 配利润表 → 验证净利润对上 | |
| 7 | 配现金流量表 → 验证净增加额对上 | 最难，放最后 |
| 8 | 录测试凭证跑一遍全流程 | 不录数据永远不知道对不对 |

## 七、常见报错与排查

| 现象 | 原因 | 解法 |
|---|---|---|
| 自定义报表某一行全是 0 | Account Category 名称不一致 | 逐字比对模板与科目上的名称 |
| 资产负债表两边不等 | "本年利润"设了 Account Category | 清空 4103 的 Account Category |
| 利润重复计算 | 同上 | 同上 |
| 固定资产金额虚高 | 没抵减累计折旧 | 该行改用公式：原值 − 累计折旧 |
| 现金流量表全空 | 没设 Cash Flow Type | 给相关科目设 Cash Flow Type |
| 导入科目表失败 | 直接导了自制的 Excel | 必须用系统模板（见下） |
| 有科目没进任何报表行 | 漏归类别 | 用"总账"核对全部末级科目是否都被覆盖 |

## 八、导入科目表的硬规则（别踩坑）

| # | 规则 |
|---|---|
| 1 | **会覆盖原有科目表** —— 只能在**新账套**或**重建科目**时用 |
| 2 | **不能有业务数据** —— 已有凭证/发票/收付款就不能导 |
| 3 | ⭐ **必须用系统模板** —— 从 `Chart of Accounts → Import` 下载模板再填，**不要自建 Excel** |
| 4 | **必须包含以下关键科目**，否则系统跑不动 |

**必须包含的关键科目**：

| 科目 | 必须的 Account Type |
|---|---|
| 应收账款 | Receivable |
| 应付账款 | Payable |
| 固定资产 | Fixed Asset |
| 折旧（累计折旧） | Accumulated Depreciation |
| 主营业务成本 | Cost of Goods Sold |
| 库存调整 | Stock Adjustment / Stock |

> 💡 **最稳的上线节奏**（业界推荐）：
> 第一步先做**"最小科目表"**（现金 / 银行 / 应收 / 应付 / 收入 / 成本 / 费用），导入并把销售、采购、库存跑通；第二步再逐步细化，补管理费用明细、税费明细等。
>
> **一次性导入 167 个科目的完整中国准则表，是新手最常踩的坑**——容易失败，且类型没设对会导致业务跑不通。
