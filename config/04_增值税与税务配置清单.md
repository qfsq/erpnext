# 04 增值税与税务配置清单

> 适用：ERPNext v15，中国境内一般纳税人
> 提醒：具体税率、优惠适用条件与备案要求，**请以现行税法及主管税务机关口径为准**，本清单为系统配置指引

---

## 一、增值税税率总览

| 税率 | 适用范围 | 常见场景 |
|---|---|---|
| **13%** | 销售或进口货物、提供加工修理修配劳务、有形动产租赁 | 软件产品、硬件销售 |
| **9%** | 交通运输、邮政、基础电信、建筑、不动产租赁、销售不动产、转让土地使用权 | 工程施工 |
| **6%** | 现代服务、生活服务、金融服务、增值电信 | ⭐ **技术开发、技术服务、软件服务** |
| **0%** | 出口货物、跨境应税行为 | |

> ⚠️ **你这类公司的关键判断**：软件**产品**（License/自有产品）按 **13%**；技术开发、技术服务、软件服务按 **6%**。**同一个合同里混着产品和服务的，要分开开票**。

## 二、增值税模板配置

### 2.1 销售税模板

**路径**：`Accounting → Sales Taxes and Charges Template → New`

| 模板名称 | 税率 | 记账科目 |
|---|---|---|
| 销售货物（13%） | 13 | 22210102 销项税额 |
| 销售服务（6%） | 6 | 22210102 销项税额 |
| 建筑服务（9%） | 9 | 22210102 销项税额 |

**配置要点**：
- `Type` 选 **Actual**
- `Account Head` 选销项税额科目
- `Rate` 填对应税率
- 设为**默认模板**或按客户/产品指定

### 2.2 采购税模板

**路径**：`Accounting → Purchase Taxes and Charges Template → New`

| 模板名称 | 税率 | 记账科目 |
|---|---|---|
| 采购货物（13%） | 13 | 22210101 进项税额 |
| 采购服务（6%） | 6 | 22210101 进项税额 |

### 2.3 附加税费

**计提基数**：实际缴纳的增值税额

| 税费 | 税率 | 记账科目 |
|---|---|---|
| 城市维护建设税 | **7% / 5% / 1%**（按所在地：市区/县镇/其他） | 222104 |
| 教育费附加 | 3% | 222105 |
| 地方教育附加 | 2% | 2221 下另设科目 |

> ⚠️ **城市维护建设税税率按企业所在地确定**，不是全国统一 7%，务必按注册地确认。

**实现方式**：用 **Tax Rule** 或**期末计提凭证**（Journal Entry）处理，不建议挂到销售单上（因为附加税基数是"实缴增值税"，不是"销项税"）。

## 三、发票台账（数电发票过渡方案）

### 3.1 为什么先做台账

**当前开源社区没有可用的金税/数电发票对接 App**（这是实测结论：搜 `erpnext+tax+china` 零结果，`erpnext+invoice+china` 只有一个 0 星的空壳仓库）。所以先做**台账**，等对接服务商 API 时直接从台账推数据。

### 3.2 自定义 DocType 设计

**新建 DocType：`电子发票台账`**

| 字段 | 类型 | 说明 |
|---|---|---|
| 发票号码 | Data | 20 位全电发票号码 |
| 发票代码 | Data | 若为纸质/老式电子发票 |
| 开票日期 | Date | |
| 发票类型 | Select | 增值税专用发票 / 普通发票 / 全电发票 |
| 蓝票/红票 | Select | 蓝票 / 红票 |
| 购方名称 | Data | |
| 购方税号 | Data | |
| 销方名称 | Data | |
| 销方税号 | Data | |
| 金额（不含税） | Currency | |
| 税率 | Percent | |
| 税额 | Currency | |
| 价税合计 | Currency | |
| 发票状态 | Select | 已开 / 已交付 / 已红冲 / 已作废 |
| 关联销售单 | Link → Sales Invoice | |
| 关联采购单 | Link → Purchase Invoice | |
| 附件 | Attach | 发票 PDF/OFD |

### 3.3 与业务单据联动

- 销售发票（Sales Invoice）提交后，通过 **Server Script** 自动生成台账记录
- 台账状态与发票状态双向同步
- 红冲时自动生成红票台账记录

## 四、⭐ 金税 / 数电发票对接：现实路径

### 4.1 三条通道

| 通道 | 说明 | 适用 |
|---|---|---|
| **① 电子税务局（手工）** | 登录各省电子税务局手工开票 | 所有企业，**不自动化** |
| **② 乐企平台（直连）** | 国家税务总局官方 API 网关，RESTful + OAuth 2.0，支持开票/查询/红冲/申报 | ⚠️ **需申请审批，门槛高**，一般是大企业/集团 |
| **③ 服务商 API** | 通过百望云、航天信息、税友等第三方 SaaS 接口 | ⭐ **中小企业主流选择** |

### 4.2 实施建议

| 步骤 | 动作 |
|---|---|
| 1 | 先做好**发票台账**（第三节） |
| 2 | 接入服务商 API（按其文档对接） |
| 3 | 写一个 Frappe 自定义 App，实现：销售发票提交 → 调接口开票 → 回写发票号/状态 |
| 4 | 保留台账作为对账依据 |

### 4.3 发票状态机设计要点

数电发票的红冲规则**不同于三联发票时代**，状态机要单独设计：

```
草稿 → 已开具 → 已交付
                  ↓
            （红冲）→ 已红冲 → 新蓝票
                  ↓
            （作废，仅限当月未认证）→ 已作废
```

> ⚠️ **别用 RPA 模拟登录电子税务局**开票 —— 金税四期实时扫描下容易被判定异常。走合规 API。

## 五、金税四期的合规要点（系统层面必须支撑）

金税四期的核心是**"以数治税"**，核查的核心是 **"四流一致"**：

| 四流 | 系统要求 |
|---|---|
| **合同流** | 合同台账，关联订单 |
| **货物流** | 出入库单，关联订单 |
| **资金流** | 收付款记录，关联发票 |
| **发票流** | 发票台账，关联订单 |

> 🔑 **含义**：传统"月底手工调账"的窗口期基本消失。ERP 必须做到**业务发生即记录、四流实时交叉校验**。
>
> **在 ERPNext 里落地**：确保 **销售订单 → 发货单 → 销售发票 → 收款单** 是一条链上贯通的单据流，且都能追溯到同一个订单号。

## 六、技术开发 / 技术转让免税

**政策依据**：财税〔2016〕36 号

| 项目 | 说明 |
|---|---|
| 免税范围 | 纳税人提供**技术转让、技术开发**及与之相关的**技术咨询、技术服务** |
| 前提 | ⭐ **需到科技主管部门认定登记**，取得备案编号 |
| 关键 | 合同要写成"**技术开发合同**"，这是业务/法务层面的动作，不只是系统配置 |
| 注意 | ⭐ **免税项目的进项税额不能抵扣**，要单独核算 |

**ERPNext 落地**：
- 建"合同台账"自定义 DocType，标记 `是否技术开发合同` + `免税备案编号`
- 按免税/应税分离核算，避免进项税抵扣错误

> 💡 你这类公司（数字化/安全/AI 项目）**大概率有可适用技术开发免税的项目**，值得和法务、税务顾问一起梳理。

## 七、配置顺序与验证

| 顺序 | 动作 | 验证方法 |
|---|---|---|
| 1 | 建税费科目（22210101 进项 / 22210102 销项 / 222104 城建 / 222105 教育附加） | 科目树上可见 |
| 2 | 建销售税模板（13% / 9% / 6%） | 开一张测试销售单，税额自动算出 |
| 3 | 建采购税模板（13% / 6%） | 开一张测试采购单，进项税自动进对应科目 |
| 4 | 建发票台账 DocType | 手工录一条能保存 |
| 5 | 配置附加税计提 | 期末计提凭证正确 |
| 6 | 建技术开发合同台账 | 能标记免税合同 |
| 7 | （有服务商后）对接开票 API | 提交发票能自动开票并回写 |

## 八、常见坑

| # | 坑 | 说明 |
|---|---|---|
| 1 | **税率挂错科目** | 销项/进项科目必须分开，否则"应交增值税"余额永远算不清 |
| 2 | **附加税挂到销售单上** | 附加税的基数是"实缴增值税"，不是销项税，应期末计提 |
| 3 | **免税项目进项税照常抵扣** | 免税项目进项税不得抵扣，要单独核算 |
| 4 | **城建税一律按 7%** | 实际按所在地为 7%/5%/1% |
| 5 | **迷信"开源金税对接"** | 实测社区空白，必须走服务商 |
| 6 | **用 RPA 开票** | 金税四期下风险高 |
| 7 | **产品和服务的合同混开票** | 13% 与 6% 要分清，否则税负错、即征即退也算不出来 |

---

## 九、一句话总结

> **能配的都先配起来**：增值税模板（13%/9%/6%）、附加税计提、发票台账（自定义 DocType）、技术开发合同免税标记。
>
> **必须写代码/买服务的只有一件**：金税 / 数电发票的真实对接 —— 走服务商（百望云/航信/税友）API 或乐企直连。
>
> **金税四期真正考的不是"能不能开票"，是"四流是否一致"** —— 这要求 ERP 里销售订单、发货、发票、收款是一条贯通的单据链，能追溯到同一个订单号。这才是系统层面要下功夫的地方。
